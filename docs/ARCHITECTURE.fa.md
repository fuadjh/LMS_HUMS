# گردش‌های اصلی و ساختار کم‌عمق

- `Domain/Academics`: مدل و قواعد مستقل زمان/مخاطب. تقویم دقیق، زمان UTC؛ خواندن و نوشتن تاریخ شمسی با منطقهٔ تهران. `AcademicRules.CheckExit` بدون SQL و UI قابل آزمون است.
- `Contracts/Academics`: قراردادهای خواندن و نوشتن، انواع نمای UI و کاتالوگ دسته‌دار مجوز.
- `Application/Academics`: درخواست‌های کم‌حجم MediatR؛ هر درخواست یک Handler دارد که به درگاه همان بخش متصل است. وابستگی به EF، Web و Infrastructure ندارد.
- `Infrastructure/Academics`: پیاده‌سازی موارد کاربرد متصل به SQL Server در همان `ApplicationDbContext`. `LmsAccess` مجوز نقش پایه + سمت داده را بررسی می‌کند. `LmsData` تراکنش‌های نوشتن را هماهنگ می‌کند. مدل مهاجرت ثابت جدا از مدل runtime است. فایل و یادآوری کارگرهای جدا از UI دارند.
- `Api/Academics` و `Web/Components/Lms`: API با `AccessApi`، همان gate نشست و پاسخ `data`؛ رابط با MudBlazor/RTL و CSS اختصاصی. `LmsBff` فقط دو مسیر ثابت انتقال را با ticket سمت سرور و CSRF در نوشتن جلو می‌برد. Bearer به JavaScript داده نمی‌شود.

| رابطه | قاعدهٔ محافظت |
|---|---|
| `ApplicationUser → InstructorProfile / StudentProfile` | کلید هر پروفایل همان GUID حساب و در نوع خودش یکتا است؛ غیرفعال‌کردن یک پروفایل حساب یا پروفایل دیگر را پاک نمی‌کند. |
| دانشکده/رشته/مقطع → برنامه → ورودی → `StudyRecord` | دورهٔ پذیرش مستقل، پروندهٔ فعال یکتا با filtered unique index. انتقال، `EndedUtc` قبلی و پروندهٔ تازه را با یک تراکنش ثبت می‌کند. |
| کاتالوگ درس → ارائه / نیم‌سال → گروه | مخاطب از دادهٔ واقعی پرونده، نه فیلتر درخواستی. هویت ارائهٔ منتشرشده و مالک آن ثابت است؛ هم‌مدرس کنترل صریح دارد. |
| ارائه → فصل → درسک/تکلیف؛ جلسه → درسک‌ها | انتشار فصل، زمان نمایش ارائه و بازشدن جلسه کنترل‌های جداگانه‌اند. ویرایش فصل منتشرشده ممنوع؛ فصل تازه به همان ارائه می‌آید. |
| ثبت‌نام → رخداد خروج، پیشرفت، تحویل؛ تحویل → فایل و نسخهٔ نمره | هیچ حذف آموزشی وجود ندارد. `Enrollment` توکن هم‌زمانی دارد و تغییر وضعیت/رخداد آن اتمیک است. رخداد خروج و دلیل ادمین از لاگ‌های یک‌ماهه مستقل‌اند. |
| نمرهٔ تکلیف/پایانی | اضافه‌شدن Revision؛ دانشجو فقط نسخه‌های منتشرشده و مربوط به خود را دریافت می‌کند. نمرهٔ خودکار آزمون به استاد نسبت داده نمی‌شود. |
| قالب خصوصی → نسخه | JSON محتوای immutable با فرمت نسخه‌دار؛ فایل‌ها خصوصی و immutable هستند، انتشار از نسخه روی ارائهٔ دیگر اثر ندارد. |
| گفتگو | اتاق مجازی با کلید ورودی؛ گروه/خصوصی متنی، دسترسی از پروندهٔ فعال. مدیر و استاد به‌سبب نقش مدیریتی یا تدریس حق مشاهدهٔ متن خصوصی ندارند. |
| یادآوری و لاگ | یادآوری بر مبنای رویداد واقعی و کارگر دوره‌ای. `OperationalEvent`/`UploadAttempt` عملیاتی و مستقل از روابط آموزشی؛ پاک‌سازی لاگ فایل آموزشی را حذف نمی‌کند. |

## تصمیم‌های قابل بازبینی

ادمین کل اختیار تغییر ترم و مخاطب عمومی دارد؛ ادمین دانشکده روی دادهٔ مربوط به دانشکده، و ادمین رشته فقط در رشتهٔ خود. در حذف مدیر، هم قلمرو ارائه و هم همان پروندهٔ دانشجو بررسی می‌شوند. ادمین رشته مجاز به تعریف درسِ کاتالوگ سراسریِ دانشکده نیست. قالب خصوصی به استاد مسئول و همان درس کاتالوگ تعلق دارد؛ برای ارائهٔ تازه، زمان بازشدن درسک‌ها و مهلت آزمون/تکلیف دوباره تنظیم می‌شوند. رفتار انتقال/جانشینی استاد پس از انتشار عمداً محافظه‌کار است؛ برنامه مالکیت تاریخی را بازنویسی نمی‌کند.

نام‌های قابل تشخیص در ممیزی یا فایل به‌جز شناسهٔ لازم خدمت ذخیره نمی‌شوند؛ کد ملی در Payload ورودی ثبت پروفایل به گردش عادی سرور تعلق دارد، نه به لاگ. فایل‌های اکسل حاوی دادهٔ واقعی‌اند، پس فقط به شکل خصوصی و موقت نگه‌داری می‌شوند. لاگ امن متن گفتگو، بازخورد، رمز، OTP، توکن یا کلید پیامک را ثبت نمی‌کند.
