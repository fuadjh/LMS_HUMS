# بانک الگو و کارگاه زمان‌بندی — نسخهٔ بررسی آفلاین

## مبنا و محدوده

این **کل Solution** در `LMS_HUMS-master.zip` است، نه پچ. شناسهٔ ZIP ورودی `82451787ec7dd1b61f05b57933459f1b986a4dd3` و SHA‑256 آن `3e6d269282c851dbf4d0cfa80ed298021a469865c42c43135014004959fdfe72` بود. نام Solution و فضای نام `ReusableAccess` است. این بسته روی آرشیو کاربر توسعه داده شد؛ شاخهٔ دیگری از مخزن راه‌دور، فایل‌های Frest، پایگاه دانشگاه و دادهٔ واقعی در آن وارد نشده‌اند. هیچ push یا merge انجام نشده است.

## ورود و گردش کار

1. با حساب استاد مسئول که `lms.teaching.template` و برای زمان‌بندی `lms.teaching.content` دارد، وارد «میز استاد ← بانک الگوهای من» شوید. برای پیوست یا کاور، مجوز فایل درسک نیز لازم است. الگو را با انتخاب درس فعال مجاز بسازید، فصل/درسک/ارزیابی و افست را تنظیم و «ذخیرهٔ نسخهٔ تازه» را بزنید. این کار ترم، ارائه یا دانشجو ایجاد نمی‌کند.
2. کارگاه در تنظیمات API پیش‌فرض **خاموش** است؛ پس از مهاجرت و آزمایش با `Lms__ScheduleStudioEnabled=true` آن را روشن کنید. برای اقدام انتشار، مجوز مستقل `lms.teaching.publish` لازم است. آموزش همچنان تنها مرجع واگذاری استاد، کد گروه و مخاطب است. استاد فقط ارائهٔ فعال، خالی و منتشرنشدهٔ واگذارشده را به‌عنوان مقصد انتخاب می‌کند.
3. روز مبنا را در تهران تعیین کنید: برای الگوی نسبی روز صفر همان روز کلاس است؛ افست شروع در ۰۸:۰۰ و «تا پایان روز» در ساعت ۰۰:۰۰ **روز بعد** به وقت تهران تفسیر می‌شود. برای تاریخ دستیِ دارای ساعت، خود ساعت واردشده مرز است. شروع نمایش ارائه از شروع کلاس جداست: زمان تنظیم‌شدهٔ موجود، وگرنه شروع اخذ، به‌عنوان پیشنهاد استفاده می‌شود؛ باید قبل از پایان اخذ باشد.
4. انتقال، به انتخاب روشنِ مبدأ منتشرشده در ترم پیشین از همان استاد، درس و خانوادهٔ الگو نیاز دارد. تاریخ‌های واقعی اقلام منطبق از روی `Kind` و کلید پایدار جابه‌جا می‌شوند و ساعت محلی حفظ می‌شود. قلم جدید به افست نسبی برمی‌گردد. سابقهٔ فاقد انتساب قابل‌اثبات فقط خواندنی است؛ تطبیق عنوانی انجام نمی‌شود. تغییر مبنا/روش، دستی‌ها را حفظ می‌کند مگر همه را با تأیید حذف کنید. سامانه منبع تأییدشدهٔ تعطیلات ندارد و برای تعطیلی تاریخ مصنوعی پیشنهاد نمی‌دهد.
5. پیش‌نمایش از Commands جداست و در دادهٔ آموزشی چیزی نمی‌نویسد. تاریخ ناقص در حد پیش‌نویس قابل ذخیره ولی برای اعمال مسدود است. پس از ذخیره، «اعمال بدون انتشار» محتوا و زمان را می‌سازد، و «اعمال و انتشار» همان کار را با انتشار در یک تراکنش انجام می‌دهد. برای «اعمال بدون انتشار» بعداً انتشار از صفحهٔ معمول ارائه/فصل انجام می‌شود. تغییر نسخه، دادهٔ رسمی یا مبدأ، نیازمند بازبینی دوباره است. مشاهدهٔ «تقویم واقعی» دادهٔ اعمال‌شده را می‌خواند، نه پیشنهادهای قدیمی.
6. فصل و درسک بازهٔ نیمه‌باز دارند. قبل از بازشدن یا بعد از پایان، بدنه و پیوند فایل درسک در View دانشجو فرستاده نمی‌شوند و دانلود مستقیم با همان شرط کنترل می‌شود. ارزیابی بعد از پایان درسک می‌تواند باز بماند، ولی نه پس از پایان فصل/ترم یا مهلت نهایی. موعد عادی اگر مهلت دیرهنگام وجود دارد، آغازِ وضعیت دیرهنگام است. آزمون چهارگزینه‌ای و تصحیح خودکار موجود است؛ پاسخ صحیح فقط در قلمرو مجاز استاد. ثبت‌نام، تحویل، پیشرفت، نمره، اعلان و کاربران به‌عنوان محتوای الگو کپی نمی‌شوند.

## معماری و مسیر فایل

- `Domain/Academics/AcademicSchedule.cs` موتور محاسبهٔ مستقل از SQL، زمان جاری و UI است. قراردادها در `Contracts/Academics/StudioContracts.cs` و پورت‌ها و Handlerها در `Application/Academics/StudioRequests.cs` هستند. `StudioEndpoints` تنها ثبت endpoint و نگاشت درخواست را انجام می‌دهد. `StudioTemplates` و `StudioScheduling` مسوول ذخیره و مجوزند؛ `StudioMaterializer` رکوردهای آموزشی را در تراکنش **در اختیار caller** می‌سازد و Handler دیگری را برای نوشتن صدا نمی‌زند. `Revision` تبدیل تداخل به 409 و کنترل اعمال تکراری را ممکن می‌کند.
- نسخهٔ جدید از `CourseTemplate` و `TemplateVersion` موجود استفاده می‌کند؛ شکل `Format=1` خواندنی باقی است؛ زمان/رابطهٔ حدسی به نسخهٔ قدیمی افزوده نمی‌شود. `OfferingScheduleDraft` سند برنامه و رسید اعمال، و `TemplateVersionMedia` پیوند رسانهٔ نسخه‌اند. FKهای تازه `NO ACTION` و رابطهٔ اختیاری درسک ارزیابی با FK مرکب هم‌فصلی تقویت شده است. مهاجرت `20261125090000_AddLmsStudio` ستون‌ها را اضافه می‌کند؛ JSON و مهاجرت‌های قبلی دست‌نخورده‌اند. Backfill پیوند فایل از JSON معتبر V1 استفاده می‌کند و به SQL Server با پشتیبانی `OPENJSON` (compatibility level حداقل 130) نیاز دارد. پایین‌آوردن مهاجرتِ مخرب به‌طور خودکار مجاز نیست؛ بازیابی نسخهٔ پشتیبان را روی کپی تمرین کنید.
- ارسال فایل از مسیر BFF موجود است. MP4، PDF، DOCX، XLSX و JPG/JPEG/PNG؛ حداکثر هر فایل آموزشی ۲۵۰٬۰۰۰٬۰۰۰ بایت و ۱۶ پیوست در هر درسک. کاور ویدئو PNG/JPEG، حداکثر ۳ MiB و ۴۰۹۶ پیکسل در هر ضلع. بررسی اندازه، سربرگ و ابعاد جای اسکن محتوای دانشگاه را نمی‌گیرد. فایل‌های بانک به‌طور خودکار حذف نمی‌شوند؛ سهمیهٔ ذخیره‌سازی و پاک‌سازی مستند با بررسی ارجاع همهٔ نسخه‌ها و ارائه‌ها لازم است. این نسخه مدیریت فیزیکی فایل رهاشده را تغییر نمی‌دهد.
- نمای جدید با Razor و CSS محدود به مؤلفه ساخته شده است. `AppModal` تنها پوستهٔ `MudDialog`، `AppFormModal<TModel>` فرم نوع‌دار و wrappers سازگار `LmsDialog`/`AppEditDialog`/`AppConfirmDialog` هستند. تقویم ماهانهٔ رخدادها همچنان نمای خواندن است. `PersianDateField` تاریخ اختیاری را خالی نگه می‌دارد، `DatePickerZO` را فقط هنگام بازکردن انتخاب‌گر ایجاد می‌کند و پس از تأیید مقدار را به فرم می‌دهد. فیلد ثبت‌نام عمومی در کنسول شمسی نمایش داده می‌شود ولی ساعت UTC می‌ماند؛ فیلدهای آموزشی ساعت تهران دارند.

## وابستگی انتخاب‌گر و محدودیت انتشار

پروژهٔ Web به‌صورت پیش‌فرض `Blazor_PersianDatePickerZO` **۳.۰.۶** را به شکل `PackageReference` دارد؛ فایل DLL، سورس بسته و فونت بسته در ZIP کپی نشده‌اند. مجوز اعلام‌شدهٔ بسته `GPL-3.0-or-later` است؛ قبل از توزیع نسخهٔ باینری یا ترکیبی، سازگاری مجوزها و منبع/شرایط توزیع را بررسی کنید. گزینهٔ `-p:UsePersianDatePickerZO=false` برای ارزیابی سازمانی بدون آن وابستگی است و **فقط ورودی نوشتاری شمسیِ همان کامپوننت** می‌دهد، نه جایگزین بی‌نام یا تقویم دوم. طبق خواستهٔ پروژه، عملکرد کامل انتخاب‌گر با حالت پیش‌فرض است.

## دروازهٔ پذیرش قبل از مرج (اجرا روی محیط آزمایشی)

```bash
dotnet restore ReusableAccess.slnx
dotnet build ReusableAccess.slnx -c Release --no-restore
dotnet test ReusableAccess.slnx -c Release --no-build
dotnet tool restore
dotnet ef migrations has-pending-model-changes --project src/ReusableAccess.Infrastructure --startup-project src/ReusableAccess.Api --context ApplicationDbContext --configuration Release --no-build
dotnet ef migrations script 20261121203400_AddUniversityLms 20261125090000_AddLmsStudio --idempotent --project src/ReusableAccess.Infrastructure --startup-project src/ReusableAccess.Api --context ApplicationDbContext --configuration Release --no-build --output studio-upgrade.sql
```

در تست SQL از یک سرور **جدا از تولید** استفاده کنید (متغیر `RA_SQLSERVER_TEST_CONNECTION`، پایگاه آزمایشی جدا توسط تست ساخته می‌شود). نصب خالی و ارتقا روی کپی را جدا چک کنید. ابتدا آزمون‌های `AcademicScheduleTests` و `LmsPersistenceTests`، بعد مرورگر روی Web/API واقعی: دو تب و خطای 409، دسترسی مستقیم خارج از قلمرو، دریافت واقعی کاور/ویدئو، روز کبیسه و نوروز، جای قرارگیری انتخاب‌گر در مودال در موبایل، Enter/Escape، پاک‌کردن تاریخ خالی بدون ایجاد مقدار، انتشار تکراری و گردش‌های قدیمی اخذ/حذف. تست عبورنکرده یا `Skipped` به‌معنی موفقیت نیست. شاهد اجرا در این ZIP از این دستورهای **پیشنهادی** جداست؛ [گزارش بازبینی](STUDIO-REVIEW.fa.md).
