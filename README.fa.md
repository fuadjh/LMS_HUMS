# ReusableAccess + سامانهٔ یادگیری دانشگاهی

**تغییرات این تحویل:** [بانک خصوصی الگو، کارگاه زمان‌بندی، انتخاب‌گر شمسی و مودال مشترک](docs/LMS-STUDIO.fa.md). [نتیجهٔ دو بازبینی آفلاین و موارد اجرا نشده](docs/STUDIO-REVIEW.fa.md).

این پوشه **تمام سورس Solution** است، نه Patch و نه نمونهٔ UI. مبنا آرشیو `ReusableAccess-master.zip` در `d66194d9dcc62b1edeac5a8a8e8544c34099518c` است. ماژول دانشگاهی در پروژه‌های موجود به‌صورت افزایشی اضافه شده؛ اجرای HTML مرجع، نصب Node/React یا اعمال بستهٔ قبلی لازم نیست. HTML ارسالی فقط مرجع بصری است و وارد فرایند ساخت نشده است.

**وضعیت:** نامزد تحویل سورس. در محیط بسته‌بندی .NET SDK، NuGet قابل‌استفاده و نمونهٔ SQL Server وجود نداشت. Build، اجرای xUnit، آزمایش نصب/ارتقا، اجرای مرورگر علیه API و آزمایش WAF را تأییدشده تلقی نکنید. [وضعیت دقیق اعتبارسنجی](docs/VERIFICATION.fa.md) و مراحل تأیید در [راهنمای استقرار](docs/DEPLOY.fa.md) آمده‌اند.

## شروع سریع (محلی)

۱. `.NET 10 SDK`، یک پایگاه آزمایشی SQL Server، و دسترسی به Feed مورداعتماد وابستگی‌های موجود را آماده کنید. از پوشهٔ حاوی `ReusableAccess.slnx` اجرا کنید:

```bash
 dotnet restore ReusableAccess.slnx
 dotnet tool restore
 dotnet build ReusableAccess.slnx -c Release --no-restore
 dotnet test ReusableAccess.slnx -c Release --no-build
 dotnet dev-certs https --trust
```

۲. برای **API**، اتصال پایگاه آزمایشی (`ConnectionStrings__DefaultConnection`) و secret مشترک Web/API (`Authentication__OpenIddict__ClientSecret`) را با User Secrets یا متغیر محیطی تنظیم کنید؛ اطلاعات اولین مدیر را با `BootstrapAdmin` بدهید. همان secret باید در محیط **Web** نیز تنظیم شود. نام و کارکرد کلیدها در [DEPLOY.fa.md](docs/DEPLOY.fa.md) آمده است. نمونهٔ تنظیمات بدون مقادیر محرمانه در `docs/api.settings.example.json` و `docs/web.settings.example.json` است. آن‌ها را بدون تأمین مقادیر لازم به‌عنوان تنظیمات اجرا کپی نکنید.

۳. قبل از اجرای API، مهاجرت‌ها را روی **پایگاه آزمایشی** اعمال و تطابق مدل را بررسی کنید:

```bash
 dotnet ef migrations list --project src/ReusableAccess.Infrastructure --startup-project src/ReusableAccess.Api --context ApplicationDbContext -c Release --no-build
 dotnet ef migrations has-pending-model-changes --project src/ReusableAccess.Infrastructure --startup-project src/ReusableAccess.Api --context ApplicationDbContext -c Release --no-build
 dotnet ef database update --project src/ReusableAccess.Infrastructure --startup-project src/ReusableAccess.Api --context ApplicationDbContext -c Release --no-build
```

۴. API و Web را در دو ترمینال، با تنظیمات مخصوص هر میزبان اجرا کنید:

```bash
 dotnet run --project src/ReusableAccess.Api --launch-profile https
 dotnet run --project src/ReusableAccess.Web --launch-profile https
```

نشانی پیش‌فرض Web: `https://localhost:7136`؛ API: `https://localhost:7443`. پس از ورود، «سامانهٔ یادگیری» را از نوار راست باز کنید. اولین ورودِ حساب تازه با سازوکار فعلی تغییر رمز موقت انجام می‌شود. Bootstrap فقط یک بار برای نصب تازه؛ سپس `BootstrapAdmin__Enabled` را غیرفعال کنید. برای پایگاه موجود، ابتدا روی کپی ارتقا را امتحان کنید؛ مدیر جدید اجباری نیست.

## از کجا شروع کنیم؟

1. ادمین کل: دانشکده ← رشته ← مقطع ← برنامهٔ رشته/مقطع ← ورودی، سپس نیم‌سال و کاتالوگ درس. نیم‌سال تدریس مهر/بهمن/تابستان دارد؛ پذیرش فقط مهر/بهمن.
2. در «استادان و دانشجویان» کد ملی را با قلمرو مقصد استعلام کنید. حساب و اولین پروفایل در یک تراکنش ثبت می‌شوند؛ پروفایل دوم به همان حساب متصل می‌شود. برای هویت موجود، نام، تماس، اعتبار ورود و وضعیت حساب تغییر نمی‌کند. وضعیت هر پروفایل جداست.
3. ارائه را در نیم‌سال به استاد مسئول و در صورت نیاز به هم‌مدرس واگذار کنید. مخاطب عمومی دانشگاه، مشترک دانشکده یا تخصصی رشته است. فهرست ورودی، محدودیت اضافه است؛ خالی یعنی همهٔ ورودی‌های واجد شرایط. نمای استاد زمان نمایش، جلسه و فصل را تنظیم می‌کند؛ نمایش، اخذ و زمان بازشدن درسک مستقل‌اند. انتشار مدیر آموزشی نمی‌خواهد.
4. در دانشجو «دروس ارائه‌شده» و دکمهٔ اخذ/خروج را ببینید. خروج دانشجو تابع بازهٔ رسمی و حذف ادمین تابع قلمرو و دلیل است. پس از بسته‌شدن ترم، تغییر آموزشی رد می‌شود. ثبت‌نام و وضعیت قبلی، تکلیف، پیشرفت و نمره پاک نمی‌شوند.
5. تکلیف متنی/فایل و آزمون چهارگزینه‌ایِ ساده اختیاری‌اند. تکلیف چند تلاش، مهلت دیرهنگام، پیش‌نویس خصوصی و انتشار نمره/بازخورد دارد. آزمون ساده خودکار تصحیح می‌شود، تطبیقی یا AI نیست. نمرهٔ پایانیِ غیررسمی را استاد مسئول جداگانه از ۲۰ منتشر می‌کند.
6. هر دو پنل تقویم جلالی و اعلان دارند. گفتگو برای دانشجویانِ ورودی فعال است؛ پیام گروهی یا خصوصی بدون پیوست، نه دستیار. ارسال پیامک را فقط ادمین کل و پس از تعریف درگاه مجاز روشن می‌کند. «درگاه پذیرفت» معادل تحویل به گوشی نیست.
7. قالب خصوصی نسخه‌دار بدون تاریخ تقویمی، ترم، دانشجو یا نتیجهٔ ارزیابی است. نسخهٔ جدید می‌تواند قواعد نسبی روز داشته باشد. استفاده از نسخه فقط روی ارائهٔ خالی و منتشرنشده؛ فصل‌های جدید می‌توانند جداگانه در ارائهٔ جاری منتشر شوند. پیش‌نمایش درس داده‌ای ثبت نمی‌کند.

## حدود و پیش‌فرض‌های مشخص

- حذف‌واضافه و مهلت‌ها شامل شروع و **غیرشامل انتها** هستند. حذف ادمین، قبل از بسته‌شدن ترم و با دلیل ۱ تا ۵۰۰ کاراکتر می‌تواند بیرون از پنجرهٔ دانشجو باشد. بازاخذ خودکارِ یک ثبت‌نام خارج‌شده فعال نشده است. انتقال پرونده، پروندهٔ قبلی را می‌بندد ولی خروج/حذف قبلی را بازنویسی نمی‌کند. بایگانی عرضهٔ جاری را متوقف می‌کند؛ FKهای آموزشی `NoAction` هستند.
- تنظیم سطح دسترسی ادمین‌های دانشکده/رشته از طریق نقش موجود در کنسول و تخصیص قلمرو در پنل LMS انجام می‌شود؛ تخصیص قلمرو مجوز پلتفرم نمی‌دهد. نقش‌های پایهٔ LMS حذف نمی‌شوند. پیوندهای مجوز خودِ مدل قدیمی با رفتار قبلی حفظ شده‌اند؛ حذف نقش قدیمیِ دارای تخصیص همچنان رد می‌شود.
- فایل: ۲۵۰ مگابایت ده‌دهی (۲۵۰٬۰۰۰٬۰۰۰ بایت) سقف فایل معمولی در برنامه، نه وعدهٔ شبکه. XLSX ورود حداکثر ۸ مگابایت و ۵۰۰ ردیف دارد. بررسی پسوند و ساختار اولیه جایگزین اسکن بدافزار یا سیاست WAF نیست. فایل در WebRoot ذخیره نمی‌شود. لاگ انقضای یک‌ماهه مستقل از سوابق و فایل‌های مربوط است.
- Excel: فقط Sheet1 و ستون‌های قالب (`student.xlsx` و `teacher.xlsx`)؛ کد ملی، موبایل و شمارهٔ دانشجویی متن‌اند. پیش‌نمایش هیچ پروفایلی نمی‌سازد. تأیید ردیف‌به‌ردیف است و تداخل/رد هر ردیف جدا نشان داده می‌شود؛ انتقال و ویرایش پروفایل موجود از Excel انجام نمی‌شود. حساب تازهٔ واردشده رمز تصادفیِ نمایش‌نداده‌شده دارد؛ ادمین کل از گردش «بازنشانی رمز» رمز موقت عملیاتی را تعیین و از کانال امن تحویل می‌دهد. قالب‌ها دادهٔ واقعی/رمز ندارند.
- استقرار پیش‌فرض تک API و تک Web روی HTTPS است. برنامه تنظیم اختصاصی فروشندهٔ WAF ندارد: برای تطبیق رد شبکه، کد پیگیری در مسیر انتقال ثبت می‌شود؛ بدون لاگ معتبر لبه، نتیجه «تأیید نشده» می‌ماند. گزارش تحلیلی، دستیار هوشمند، تحلیل تسلط و کارنامهٔ رسمی در این تحویل نیستند.
